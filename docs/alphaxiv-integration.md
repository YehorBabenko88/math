# alphaXiv research integration proposal

Status: design only; no external account, API key, or MCP endpoint is connected.

## Verified interfaces
- alphaXiv MCP: https://api.alphaxiv.org/mcp/v1 (Streamable HTTP; OAuth 2.1 or API key for headless use). See https://www.alphaxiv.org/docs/mcp
- alphaXiv public API reference: https://api-dev.alphaxiv.org/
- alphaXiv comments must be authored by people, not generated by AI: https://www.alphaxiv.org/commentguidelines

## Proposed isolated read-only pipeline
1. Search for papers relevant to a declared mathematical transformation or experiment.
2. Normalize paper metadata (arXiv identifier, version, title, authors, retrieval timestamp, canonical URL, license if available).
3. Save a provenance-only evidence node in the experiment record; never import article text as executable instructions.
4. Require human approval before translating a paper's claims into an adapter specification.
5. Reproduce claims against independent numerical baselines and unit tests; label results as reproduced, contradicted, or untested.
6. Cache references by paper version and avoid storing copyrighted full text without permission.

## Security and reliability
- Run MCP/API calls server-side or through a trusted local bridge, never from the static browser UI with an exposed key.
- Separate untrusted paper content from instructions; sanitize titles and summaries before rendering.
- Enforce request budgets, timeouts, retries, rate limits, and provenance version pinning.
- Do not automatically publish AI-written comments or claim that a preprint is peer-reviewed.
- Keep alphaXiv optional: local experiments must work offline.

## Integration gates
- API access and terms reviewed
- Minimal read-only client with mocked tests
- Versioned reference schema
- Security audit
- Human-in-the-loop experiment proposals
