# Local durable book ingestion queue

Requires Node.js 22.13 or newer with built-in `node:sqlite`. The async repository interface allows a future PostgreSQL implementation; this implementation is a single-host local pilot. It starts no worker, external request or background ingestion.

`await openBookQueue({directory, now: Date.now, maxAttempts: 3})` returns the repository. `now` returns integer epoch milliseconds and is injectable for tests. `maxAttempts` is persisted (1–10); reopening/importing with a different value is rejected. Use a trusted private local directory outside the repository. Directory symlinks/junctions and symbolic-link ancestors are rejected, as are linked storage files. This does not protect against an administrator concurrently replacing the filesystem. Network filesystems and multi-host use are unsupported.

Methods are asynchronous:

- `enqueue({sourceHash, edition, page, extractionVersion, payload})`: lowercase SHA-256 source hash, exact edition string, 1-based page, extraction version and bounded local JSON object. The ID is SHA-256 of the JSON array `[sourceHash, edition, page, extractionVersion]`. Duplicate enqueue returns the original job, including its original payload and any completed result.
- `acquire({workerId, leaseMs, jobId?})`: returns a job with cryptographically random `token`, `attempts`, and `leaseUntil`, or `null`. Optional `jobId` is an exact lowercase 64-character hex ID and restricts acquisition to that job; unknown, completed or currently leased jobs return `null` without acquiring a different queued job. Leases last 1–86,400,000 milliseconds. Each acquisition consumes an attempt. Expired leases recover on open/acquire, becoming queued or permanently failed when attempts are exhausted.
- `checkpoint(id, token, object)`: persists a bounded JSON checkpoint, retained through retries. Workers must validate that a resumed checkpoint matches their extraction protocol.
- `complete(id, token, {result, metrics})`: stores a JSON object result and numeric nonnegative metrics. Completed jobs cannot be overwritten.
- `fail(id, token, {code, retryable: true})`: stores a bounded uppercase error code and requeues until attempts are exhausted. `retryable: false` fails immediately. Error codes must match `[A-Z][A-Z0-9_]{0,63}`; do not put document content or credentials into identifiers or codes.
- `recordReview(id, receipt)`: stores one strict `{candidateDigest, decision, reviewer, reason, reviewedAt, visualVerified}` receipt on a completed job whose `result.digest` matches. Decision is `approved` or `rejected`; timestamp is an existing exact ISO UTC timestamp with milliseconds. Reviewer/reason are bounded plain text. It writes `result.reviewReceipt` and sets numeric `metrics.reviewDecisions` to 1. An identical receipt is idempotent even with reordered keys; a conflicting receipt rejects. This is trusted-caller storage only: the queue does not authenticate humans or verify candidate mathematics. The caller must independently run the review module's candidate/context/numerical checks before invoking it. Queue-directory write access already grants authority to modify local state.
- `get(id)` and `list()` return detached snapshots, including checkpoint and result. Treat these and exported backups as private local document data.
- `exportSnapshot()` returns validated `{schemaVersion:1,maxAttempts,jobs}` JSON data. Save it explicitly with private filesystem permissions. `importSnapshot(objectOrJSON)` validates everything before mutation and only restores into an empty store with matching attempts policy. All restored active leases are invalidated; old workers cannot complete restored jobs. A new acquisition consumes another attempt.

States are `queued`, `leased`, `completed`, `failed`. Every completion, failure and checkpoint requires the current unexpired lease token; equality is checked with `timingSafeEqual`. Lease expiry is inclusive (`now >= leaseUntil`). There is no lease-renewal API; choose a bounded lease sufficient for one page operation. Wall clocks must be synchronized for cooperating local processes.

The authoritative store is `queue.sqlite`, not an in-memory queue or a JSON file. SQLite `BEGIN IMMEDIATE` transactions, `synchronous=FULL`, and DELETE journaling provide atomic persistence and OS-managed cross-process lock recovery after process termination. Busy waits are bounded to five seconds. No stale application lockfile is unlinked and no fencing relies on process IDs. Queries use prepared statements; returned content is never executed. Queue JSON snapshots, not copied live database files, are the supported backup format. Schema version 1 is explicit; unsupported versions fail closed and need a reviewed migration.

At most 1,000 jobs and 8 MiB of total validated JSON are allowed. Each payload is at most 64 KiB; result/checkpoint inputs are at most 256 KiB. JSON depth, node count and array lengths are bounded; nonfinite numbers, cycles, accessors, custom prototypes and dangerous object keys are rejected without calling getters or `toJSON`. Numeric-only metrics prevent extracted text from being stored as telemetry. Errors contain static messages rather than paths, source text, SQL or parser details. No logging is performed.

Corrupt SQLite files, missing metadata, unsupported schema and malformed persisted JSON fail closed. The queue never automatically resets a corrupt store. Keep the damaged database for investigation and restore a verified snapshot into a different empty directory. Orphan temporary files are ignored. SQLite's supported recovery journal must remain beside its database until recovery completes.

Tests include two repository instances, two independent processes, restart, stale tokens, exact lease expiry, bounded retries, checkpoint persistence, dedup after completion, killed writer rollback/lock recovery, corruption, snapshot validation/restore and symlink rejection. They use synthetic local metadata only.
