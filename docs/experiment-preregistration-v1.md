# Experiment preregistration — Round 21 isolated development

The existing codec encodes every preregistration and terminal payload. The pure contract binds immutable manifest, cohort, input, seed, budget policy, snapshot, fit and availability references before execution. Its attempt identity remains compatible with the existing terminal DTO. Semantic identity removes discovery enumeration and retry ordinals, while retaining scientific bindings. Reordered discovery rosters therefore cannot purchase another execution of the same semantic trial.

The existing PostgreSQL ledger is the sole reservation and receipt store. There is no additional queue or store. SQL remains outside the production migration manifest and refuses any database other than `math_experiment_test`, any provisioning owner other than `math_experiment_owner`, and any server outside PostgreSQL 18. The adapter additionally requires `math_experiment_host` and a dedicated physical connection supplied by a trusted host. The pool argument is retained for API compatibility; it is never used.

Each command takes a transaction advisory lock before locking budget or attempt rows. Every new receipt, including claim/start refusal, charges one unit of the existing policy proposal/admission credit; only a genuinely new semantic trial also charges an attempt. No second budget exists. Exact command replays and lookups do not recharge, even at exhaustion. The command table is therefore bounded by provisioned admission limits. Provisioners must allow enough admission credit for the entire state machine; exhaustion can strand an attempt before terminal recording. Exhaustion or binding conflicts roll back the entire transaction, including counters. Exceptions retain no command and charge no credit. Budget policy/limits, canonical preregistration bytes and receipts cannot be updated or deleted through ordinary SQL. The provisioning owner remains trusted and can change schema definitions.

Concurrent semantic duplicates return the canonical stored attempt and preregistration references, including when their discovery IDs differ. Durable commands retain the canonical attempt reference, so replay and lookup recover that same identity. Callers must use the returned canonical reference rather than their requested identity.

The state machine is `REGISTERED → CLAIMED → STARTED → TERMINAL`. A claim fixes a worker reference and an unpredictable UUID token. No reclaim, token replacement or backward transition exists. Start requires both worker and token and can return `fresh: true` only after one successful COMMIT. The same command and every subsequent start return `fresh: false`. Finalization requires the same claim and immutable terminal bytes. Failed workers may permanently strand work; this is deliberately at most once, with no exactly-once completion claim.

A lost COMMIT response raises `COMMIT_UNKNOWN`, including when closing the broken connection also fails. The adapter never retries or dispatches. Recovery uses `lookup(commandRef)` in a read-only transaction and returns the original operation/outcome plus canonical attempt, current state, worker/token and terminal bytes. Lookup always has `fresh: false` and `executionAuthority: false`; recovered STARTED receipts never authorize dispatch. The outcome describes the command at commit; the state describes the attempt at lookup. No adapter method performs kernel execution. A trusted dispatcher may consume only a directly returned, successfully committed fresh start once. Reusing such an object outside this protocol is outside the adapter's guarantees.

Trusted resolvers must independently verify exact preregistration and terminal evidence. The adapter enforces resolver presence and affirmative responses; it does not authenticate arbitrary workers, prove the resolver implementation or provide a lease. Worker-reference/token checks are fences within this trusted-host model. Function-only host grants protect tables; credentials and connection-factory custody remain host responsibilities. All authority flags remain false. Holdout, trading and protected integration are excluded.

## Validation

`node --test tests/experiment-preregistration.test.mjs tests/experiment-postgres-live.test.mjs`

The live test requires explicit `MATH_EXPERIMENT_OWNER_URL` and `MATH_EXPERIMENT_HOST_URL` for the reviewed isolated PostgreSQL 18 instance. It validates database/owner identity before resetting only `math_experiment_lab`, applies this SQL, provisions one budget and grants host functions without table privileges. Never point these variables at an existing application database. Without both URLs the live case explicitly skips.

Round 21 executed all eight tests with zero skips on isolated PostgreSQL 18.1. The live case covers concurrent different-ID semantic reservation, canonical replay, changed binding conflict, immutable policy/preregistration, budget rollback and bounded command admission, claim recovery, wrong-worker rejection, competing starts, terminal immutability, host table denial, and actual server COMMIT followed by a simulated transport error. Recovery observes STARTED but never grants a fresh start. This is isolated component evidence, not production acceptance or a physical scientific result.
