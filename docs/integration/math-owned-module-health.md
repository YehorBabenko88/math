# Math owned-process functional health

The existing Math HTTP engine additionally serves `GET /internal/v2/module/health`. Standalone mode remains available with existing endpoints; the private endpoint returns unavailable unless an owned profile is configured. Any partial or malformed owned profile fails startup before listening, numerical evaluation, worker creation or backend-module import. Closed failure output contains no environment, token, Git stderr or private path.

The launcher must supply `UNIFIED_MODULE_ID=math`, a numeric `UNIFIED_MODULE_VERSION`, `UNIFIED_RELEASE_ID`, a 64-lowercase-hex `UNIFIED_INSTANCE_TOKEN`, exact externally admitted `UNIFIED_SOURCE_COMMIT`, absolute externally pinned `UNIFIED_GIT_EXECUTABLE`, and its `UNIFIED_GIT_SHA256`. These values come from the deployment trust boundary, never from candidate self-reported provenance. There is no root/environment override API: source is bound to this module's actual imported repository. Real Git source capsules are required.

Before numerical modules load, the bounded startup check rejects linked source/config paths, alternate object stores, replacement refs, grafts, custom attributes and unsafe local Git configuration. Include/filter/worktree config and non-false fsmonitor are rejected before Git runs; explicit null hooks/attributes paths from the capsule profile are accepted. All source and Git metadata paths are inspected from filesystem root to leaf before any descendant probe or read. HTTP alternates and promisor pack metadata are rejected; commands force `GIT_NO_LAZY_FETCH=1` and disable global/system config, optional locks, hooks, fsmonitor and replacement refs. Local identity checks must not trigger network object retrieval. Source status/index must be clean, and raw bytes of every tracked regular file across the complete commit (including book/catalog/resources outside `src`) must hash to their Git blobs even when index flags hide worktree changes. Commands have individual and total time/output bounds; source file counts and bytes are bounded. A known externally pinned Git binary may have vendor hardlinks; source/config files must be unique regular files.

The actual engine then evaluates a fixed 500-point constant-price numerical baseline and the scientific DAG `[1,2,3] -> x*2 -> [2,4,6]`. These are explicitly synthetic offline checks. Failure blocks owned startup. Success means **offline Math API functional readiness only**: it grants no physical, exchange-source, historical completeness, live-market, training, execution or trading authority. It does not replace authenticated historical receipts or runtime OS attestation.

An exact single normalized HTTP `Authorization: Bearer <instance-token>` is required, checked with `timingSafeEqual`. Duplicate/malformed authorization is denied, query variants are rejected, and non-GET methods cannot mutate state. Successful JSON has exactly `module_id`, `version`, `release_id`, `instance_token`, `ready`. The instance profile is frozen; in-process profile drift makes readiness false. Health requests do not run Git or create workers. Source qualification is a startup snapshot, not continuous protection against a hostile administrator; private source namespaces and ProcessDriver pins remain necessary.

Implementation plan within the approved module-adapter design: exercise actual clean disposable Git fixtures over HTTP (RED), implement guarded startup plus synthetic self-test and private endpoint, run the existing bounded/scientific compatibility suites, then commit/re-pin and perform a genuine ProcessDriver-owned Node proof. No controller, dependencies, locks or deployment policy are changed by this adapter.
